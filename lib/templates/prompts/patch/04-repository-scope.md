# Repository Scope

Use only the repositories and worktrees listed in `Patch Runtime Context`. Map the Jira card to a repository using, in order: the latest human reply, exact repository labels/fields or `Repository:` lines, file paths, related Jira context, matching Jira-key history, and focused code evidence. A repository name inferred only from a vague keyword is not enough. A repository mentioned in a suggestion or example is not an additional target when an authoritative `Repository:` field or label identifies the scope.

If the latest human Jira reply names one or more exact registered repositories, treat that reply as the repository selection and inspect every named worktree. If several repositories are required by the same concrete flow, list all of them and explain the dependency. Do not add an unlisted repository just because a keyword matches. Only stop with `patch_status: blocked` when no registered repository has credible evidence, the selected worktree is unavailable/dirty, or the Jira scope is genuinely contradictory; ask one question in that case.
